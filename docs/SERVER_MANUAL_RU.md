# Полное руководство по ServerFlow (v2.0)

Это руководство поможет вам настроить все аспекты работы сервера: от системы лобби до автоматического кика AFK-игров.

---

## 1. Концепция состояний (Flow)
ServerFlow управляет сервером через систему состояний:
- **Lobby**: Центральный хаб (обычно карта de_mirage). Здесь игроки выбирают, во что играть дальше.
- **PreMatch**: Фаза разминки перед игрой. Здесь происходит сбор команд и Ready-check.
- **Match**: Сама игра. Плагин уходит в фон, чтобы не мешать.
- **PostMatch**: Экран статистики после игры. Здесь решается, куда сервер пойдет дальше (Continuity).

---

## 2. Настройка сценариев (`scenarios.cfg`)
Сценарии — это "рецепты" для сервера. Вы можете создать любое количество режимов.
Ключевые параметры:
- `game_type` / `game_mode`: Технические ID режима CS:GO (например, 1/2 для Danger Zone).
- `require_prematch` (0/1): Нужно ли фаза разминки и сбора команд.
- `team_policy`:
  - `auto`: Сервер сам распределяет игроков.
  - `manual`: Игроки сами выбирают сторону.
  - `none`: Распределение не требуется (например, для режима "каждый сам за себя").
- `ready_policy`:
  - `required`: Игра не начнется, пока все не нажмут `!ready`.
  - `optional`: Игра начнется по таймеру, даже если не все готовы.

---

## 3. Система готовности и команд
- **`!ready` / `!unready`**: Основные команды для игроков в фазе PreMatch.
- **`!team`**: Открывает меню выбора команды или управления готовностью.

---

## 4. Контроль AFK (`AFK Monitor`)
Плагин следит за активностью игроков, чтобы сервер не простаивал.
- **`sm_serverflow_afk_policy`**:
  - `0`: Выключено.
  - `1`: Только предупреждение в чат.
  - `2`: Перенос в наблюдатели (по умолчанию).
  - `3`: Кик с сервера.
- **`sm_serverflow_afk_seconds`**: Через сколько секунд бездействия применить правило (минимум 30 сек).

---

## 5. Система голосования
Подробно описана в отдельном документе: [VOTING_SYSTEM_RU.md](./VOTING_SYSTEM_RU.md)
**Кратко:**
- Поддерживает 5 режимов (Мажоритарный, Рулетка, Порог и др.).
- Настраивается кворум (явка) и защита от повторов (History-Bias).

---

## 6. Административные команды
- **`sm_queuescenario <id>`**: Подготовить смену режима (например, `!queuescenario comp`).
- **`sm_confirmpending`**: Применить подготовленную смену (мгновенно).
- **`sm_cancelpending`**: Отменить запланированную смену.
- **`sm_status_verbose`**: Техническая информация о состоянии плагина для отладки.

---

## 7. Полный список ConVar
| Переменная | Значение по умолчанию | Описание |
| :--- | :--- | :--- |
| `sm_serverflow_vote_duration` | 20.0 | Время на голосование |
| `sm_serverflow_vote_min_players` | 4 | Минимум игроков для старта голосования |
| `sm_serverflow_late_join_policy` | 1 | Что делать с зашедшими посреди матча (1 = в спектры) |
| `sm_serverflow_pending_confirm_window` | 20 | Сколько времени у админа на подтверждение смены режима |
| `sm_serverflow_verbose` | 1 | Подробные логи в консоль (0/1) |

---

## 8. Советы по настройке
- Если вы хотите "быстрый" сервер для друзей: ставьте `ready_policy optional` и `sm_serverflow_vote_threshold 3`.
- Если у вас серьезный соревновательный сервер: используйте `ready_policy required` и `sm_serverflow_vote_quorum 0.6`.
