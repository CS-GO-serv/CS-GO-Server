# Система голосования ServerFlow (v2.0)

Этот документ описывает все настройки и механики системы голосования, которые позволяют гибко адаптировать сервер под нужды игроков.

## 1. Основные режимы (`sm_serverflow_vote_policy`)
Эти режимы определяют, **как** рассчитывается победитель в конце голосования.

- **0 (Majority)**: Побеждает вариант с максимальным количеством голосов (стандарт).
- **1 (Roulette)**: Шанс победы пропорционален числу голосов. (9 голосов = 90% шанс).
- **2 (Equal Weight)**: Каждый вариант, набравший хотя бы 1 голос, получает равную долю шанса (100% / Кол-во вариантов).
- **3 (Random Top 2)**: Сервер находит два лидера и выбирает между ними 50/50.
- **4 (Threshold)**: Побеждает тот, кто первым набрал число голосов, указанное в `sm_serverflow_vote_threshold`.

---

## 2. Глобальные механики (Опциональные)
Эти настройки работают параллельно с любым выбранным выше режимом.

### Порог (Threshold / Flash Win)
- **`sm_serverflow_vote_threshold`** (по умолчанию 5)
  - Если режим набирает это количество голосов, голосование завершается **мгновенно**, не дожидаясь таймера.
  - Установите в 0, чтобы отключить эту проверку.

### Кворум (Quorum)
- **`sm_serverflow_vote_quorum`** (0.0 - 1.0, по умолчанию 0.0)
  - Минимальный процент игроков (от 0 до 100%), которые должны проголосовать для признания результата.
  - Например, 0.5 означает, что если из 10 игроков проголосовало только 4 — результат аннулируется (сервер остается в текущем режиме/сценарии).

### Консенсус (Consensus)
- **`sm_serverflow_vote_consensus`** (0.0 - 1.0, по умолчанию 0.0)
  - Минимальный процент голосов для победы одного варианта (только для режима Majority).
  - Например, 0.6 означает, что лидер должен набрать больше 60% всех отданных голосов. Если лидер набрал 51% — это считается отсутствием консенсуса, и сервер переходит к дефолтному действию (обычно Lobby).

---

## 3. Анти-Повтор (History-Bias)
Механика, предотвращающая бесконечное повторение одних и тех же режимов/карт.

- **`sm_serverflow_vote_history_bias`** (0/1)
  - Главный переключатель. Включает/выключает учет истории.
- **`sm_serverflow_vote_history_size`** (1-10)
  - Сколько последних сыгранных сценариев помнить.
- **`sm_serverflow_vote_history_mode`** (0/1)
  - **0 (Weight)**: Снижать шанс выпадения недавних режимов (используется вес).
  - **1 (Block)**: Полностью блокировать недавние режимы (они будут отображаться, но их шанс равен 0).
- **`sm_serverflow_vote_history_weight`** (0.0 - 1.0)
  - Множитель веса для недавних режимов (если `history_mode` = 0).
  - Например, 0.2 означает, что шанс выпадения недавнего режима будет в 5 раз меньше обычного.

---

## 4. Общие настройки
- **`sm_serverflow_vote_duration`**: Длительность голосования в секундах.
- **`sm_serverflow_vote_cooldown`**: Кулдаун между голосованиями.
- **`sm_serverflow_vote_min_players`**: Минимальное число живых игроков для старта голосования.

---

## 5. Примеры конфигурации

### "Жесткая демократия" ( Majority + Quorum + Consensus)
```cfg
sm_serverflow_vote_policy 0
sm_serverflow_vote_quorum 0.6         // Нужно 60% явки
sm_serverflow_vote_consensus 0.65     // Лидер должен набрать 65% голосов
sm_serverflow_vote_history_bias 1
sm_serverflow_vote_history_mode 1      // Полная блокировка повторов
```

### "Веселая рулетка" (Roulette + History Bias)
```cfg
sm_serverflow_vote_policy 1
sm_serverflow_vote_history_bias 1
sm_serverflow_vote_history_mode 0      // Недавние режимы просто реже выпадают
sm_serverflow_vote_history_weight 0.1  // В 10 раз реже
```
