# Ключевые идеи из ранней разработки (Kontext)

> [!NOTE]
> Это выжимка из ChatGPT-переписки о начальном проектировании плагина.
> Часть концепций уже реализована в ServerFlow, часть — roadmap, часть — исходная мотивация проекта.

---

## 1. Исходная мотивация

- **Цель**: сервер для компании ~16 друзей из Казахстана, России, Беларуси для совместной игры в Danger Zone и другие режимы CS:GO Legacy.
- **Боль**: стандартное управление сервером через консоль неудобно, нет нормального UX для выбора режимов, ручного распределения по сквадам, переключения карт.
- **Идея**: не просто «mode vote plugin», а **полноценная серверная платформа** — «Game Night Hub», вечерний хаб для компании.

---

## 2. Философия UX (ключевое)

### 2.1 Intent-first, не settings-first
Текущая проблема: интерфейс построен по логике настроек (`какой режим? → какой размер команды? → как распределять? → применить или голосовать?`).

**Правильный подход**: интерфейс по логике намерения игрока:
- «Во что играем?» → «Solo / Duo / Trio?» → «Сами собираемся или авто?» → Подтверждение → Старт.

### 2.2 Один экран = одно решение
- Игрок видит только следующий логичный вопрос
- Никаких лишних технических терминов
- Поток предсказуем и одинаков каждый раз

### 2.3 Наглядность состояния сервера
Игрок всегда должен понимать 4 вещи:
1. **Где мы сейчас** (Lobby / PreMatch / Match / PostMatch / Transition)
2. **Что выбрано следующим** (Next: DZ Duo Open)
3. **Кто это решил и как** (Vote / Admin override / Default rotation)
4. **Когда вступит в силу** (After match / In 12 sec / Waiting ready-check)

### 2.4 Три слоя видимости
| Слой | Назначение | Пример |
|---|---|---|
| Чат-события | Мгновенные уведомления | «Голосование началось», «Админ поставил override» |
| Постоянный статус | Компактная сводка | State: PreMatch · Next: DZ Duo · Ready: 5/8 |
| Полный экран | По запросу `!play` / `!status` | Детальная информация с действиями |

### 2.5 Критика текстовых меню
- SourceMod-меню — это **инструмент админа**, а не игровой интерфейс
- Если интерфейс ощущается как «админская утилита» — это провал UX
- Нужно исследовать нативные поверхности CS:GO (радиальное меню, buy menu, планшет) прежде чем скатываться в текстовые списки

## 3. State Machine — каркас всего

### 3.1 Основные состояния
```
Lobby → PreMatch → Match → PostMatch → Transition → (Lobby или Match)
```

### 3.2 Подфазы PreMatch
| Подфаза | Назначение |
|---|---|
| Setup | Показать выбранный сценарий и карту |
| Teams | Сбор сквадов / ручной выбор |
| Ready | Подтверждение готовности |
| Lock | Короткое окно «стартуем через N сек» |

### 3.3 Подфазы PostMatch
| Подфаза | Назначение |
|---|---|
| Results | Показ результатов матча |
| Decision | Выбор «что дальше» (ещё / смена карты / смена режима / Lobby) |
| Confirm | Финальное подтверждение перед применением |

### 3.4 Подфазы Transition
| Подфаза | Назначение |
|---|---|
| Validate | Проверить валидность сценария и карты |
| Apply | Применить cfg / параметры |
| ChangeLevel | Смена карты |
| Recovery | Аварийный fallback в Lobby |

## 4. Сценарии (Scenario Model)

**Сценарий — не режим, а пакет всех настроек:**
- `id`, `display_name`, `base_mode` (dz / comp / casual)
- `map_pool` (maplist)
- `squad_policy` (auto / open / captain)
- `spectator_policy` (team-only / all / none)
- `respawn_policy`
- `postmatch_default_action` (next map / vote / lobby)
- `warmup_policy`, `ready_policy`, `ready_threshold`
- `ui_visibility`, `permissions`

**Ключевой принцип**: новый сценарий добавляется через конфиг, а не через правку кода плагина.

---

## 5. PostMatch: «продолжать вечер, а не прерывать»

Главное решение: **по умолчанию — продолжать текущий сценарий на следующей карте**, а не возвращать в Lobby.

### Почему:
- Компания друзей чаще хочет «ещё одну»
- Lobby после каждого матча раздражает
- Сохранение темпа вечера важнее лишнего экрана выбора

### Когда возвращать в Lobby:
- Явный выбор игроков
- Админ отправил
- Не хватает игроков
- Ошибка / невалидный сценарий (fallback)

---

## 6. Pending/Confirm: «никогда не применять мгновенно»

### Три стадии решения:
1. **Proposed** — предложено
2. **Selected** — победило в голосовании / выбрано админом
3. **Applied** — реально применено сервером

### Окно подтверждения (Confirm Window):
- 8–15 секунд видимости решения
- Видно: что выбрано, кем, когда применится
- Можно: подтвердить / отменить / переопределить
- За 3–5 сек до применения → состояние **Locked** (только админ может отменить)

## 7. Ready-check и Countdown

### Гибкая модель готовности (по сценарию):
| Политика | Описание |
|---|---|
| All Ready | Все должны нажать ready |
| Percentage | Например 60%, 70%, 80% |
| Minimum Count | Например ≥8 игроков |
| Captain Confirm | Для кастомных вечеров |
| Timeout + Fallback | Если долго никто не готов — сервер решает сам |

### Countdown при позднем подключении:
- Идёт отсчёт → заходит новый игрок → **отсчёт сбрасывается**, ждём пока все готовы
- Это важнее, чем «запустить быстрее»
- Причина сброса должна быть видна всем

---

## 8. AFK и Late Join

### AFK:
- Не блокирует матч бесконечно
- Исключается из ready-pool
- Переводится в spectator по таймауту
- Политика настраивается в конфиге (`afk_timeout`, `afk_action`)

### Late Join:
- **Soft policy**: countdown сбрасывается, новичок присоединяется
- **Hard policy**: новичок в spectator до safe-point
- Зашедший посреди Match идёт в наблюдатели

---

## 9. Админ = игрок + оператор

### Как игрок:
- Тот же UI, голосование, те же состояния

### Как оператор — три уровня override:
| Уровень | Когда применится | Кейс |
|---|---|---|
| Soft | После текущего матча | Основной безопасный вариант |
| Round-safe | На ближайшей безопасной точке | Конец раунда / разминки |
| Hard | Немедленно | Аварийная кнопка |

### Админ НЕ должен:
- Ломать state machine
- Применять невалидный сценарий/карту
- Обходить логирование
- Руками крутить отдельные cvar'ы на ходу

## 10. Команды (минималистичная модель)

### Для игроков — 2 основные точки входа:
- `!play` — единый вход в выбор режима
- `!team` — управление сквадом (только когда актуально)

### Для админа — быстрые пресеты:
- DZ Solo / DZ Duo Auto / DZ Duo Open / DZ Trio Auto / DZ Trio Open
- Competitive / Casual / Lobby
- Override / Cancel / Restart / Health check

---

## 11. Конфиг: «всё настраиваемо, всё с комментариями»

### Все числовые/временные/процентные параметры — в конфиге:
- `countdown_duration` (секунды)
- `confirm_window_duration` (секунды)
- `ready_threshold_percent` / `ready_threshold_count`
- `vote_cooldown` / `vote_min_players` / `vote_quorum_percent`
- `afk_timeout` / `afk_action`
- `late_join_policy` (soft / hard)
- `postmatch_default_action` (continue / lobby / vote)
- `admin_override_confirm_window`
- `map_repeat_protection_count`

### Каждый параметр — с пояснением для человека.

## 12. DZ-специфика (Danger Zone)

### Ключевые cvar'ы:
| Cvar | Назначение |
|---|---|
| `sv_dz_team_count` | Размер отряда (1=solo, 2=duo, 3=trio) |
| `sv_dz_jointeam_allowed` | Разрешить ручной выбор сквада |
| `sv_dz_autojointeam` | Авто-раскид по отрядам |
| `sv_dz_enable_respawn` | Вкл/выкл респавнов |
| `sv_dz_enable_respawn_solos` | Респавны в соло (по умолчанию выкл) |
| `sv_dz_last_respawn_wave` | До какой волны разрешены респавны |
| `mp_forcecamera` | 0=любая команда, 1=только своя, 2=никто |
| `tv_enable` | Включить GOTV (лечит зависание камеры после смерти) |

### Проблема mp_forcecamera:
- `0` нужен для solo (иначе зависшая камера)
- `1` нужен для squads (иначе слив инфы врагам)
- **Решение**: автоматическое переключение через плагин по `sv_dz_team_count`

### Идея «второго шанса» (Solo Revive):
- `sv_dz_enable_respawn_solos 1` — встроенная механика
- Для кастомного «1 токен self-revive как в Warzone» — нужен SourceMod-плагин

## 13. Распределение по командам

### Режимы набора:
| Режим | Описание |
|---|---|
| Open Join | Игроки сами через `dz_jointeam` |
| Captain Draft | Капитаны по очереди набирают |
| Keep Previous | Сохранить сквады с прошлого матча |
| Auto-Fill | Нераспределённых дораскидать автоматически |
| Lock Teams | После ready — нельзя менять |

## 14. Ротация карт

- Защита от повтора последних N карт
- Fallback default map
- Поддержка preferred maps с весами
- Голосование за 2–4 карты из текущего сценария

## 15. Приоритеты решений

```
1. Emergency admin action

3. Successful player vote
4. Scenario default postmatch action
5. Fallback to Lobby
```

## 16. Техническая база

- **Движок**: CS:GO Legacy, App ID 740
- **Моддинг**: Metamod:Source + SourceMod
- **Возможности**: SDKHooks, DHooks, entity manipulation, game events, timers, usermessages
- **Ограничения**: нет контроля клиентского рендера/UI (Panorama/Scaleform), нет client-side prediction
- **Хрупкость**: DHooks/signatures ломаются при обновлениях игры
